## Verification and recovery

Existing candidate package evidence is four 148-pass/19-opt-in-skip runs plus
10 installed consumer contracts. Final versioned artifact checks must record
their own identities. Publication takes the successful CI run's artifacts,
without rebuilding between verification and upload. Invalid source runs,
prerelease/version mismatches and incomplete distributions must fail before
the upload job. Missing PyPI account binding leaves publication pending;
it does not permit a token to be sent through chat or an unverified upload.

Retain worktrees, source commits and build/test logs. Do not overwrite an
existing PyPI version or move an existing release tag. If publication partially
succeeds, inspect the registry and exact file digests before deciding recovery.
